## 1. Deployment Options

| Option | Pros | Cons | Recommended for |
|---|---|---|---|
| **Neo4j AuraDB (managed)** | Zero ops, auto-scaling, HA built-in | More expensive at scale | MVP / early launch |
| **Self-hosted Docker** | Full control, cheaper at scale | You manage upgrades, backups | Post 10k MAU |
| **Neo4j on EC2** | Good performance, AWS-native | Manual ops, no auto-scaling | Mid-scale |

**Recommendation for Phase 2 launch:** Start with AuraDB Free tier (enough for dev/staging), move to AuraDB Professional for production, evaluate self-hosted at 50k+ items per user.

## 2. Docker Setup

For local development and self-hosted deployment:

```yaml
# docker-compose.yml (add to existing stack)
services:
  neo4j:
    image: neo4j:5.18-community
    container_name: secondbrain-neo4j
    ports:
      - "7474:7474"   # HTTP browser
      - "7687:7687"   # Bolt protocol (driver connection)
    environment:
      NEO4J_AUTH: neo4j/${NEO4J_PASSWORD}
      NEO4J_PLUGINS: '["apoc"]'                  # APOC for utility procedures
      NEO4J_dbms_memory_heap_initial__size: 512m
      NEO4J_dbms_memory_heap_max__size: 2G
      NEO4J_dbms_memory_pagecache_size: 1G
    volumes:
      - neo4j_data:/data
      - neo4j_logs:/logs
    healthcheck:
      test: ["CMD", "cypher-shell", "-u", "neo4j", "-p", "${NEO4J_PASSWORD}", "RETURN 1"]
      interval: 30s
      timeout: 10s
      retries: 5

volumes:
  neo4j_data:
  neo4j_logs:
```

## 3. Node Labels

### `:Item`

The only node label in Phase 2. Each node mirrors a row from the PostgreSQL `items` table, but stores only the fields needed for graph operations — not the full content.

```cypher
(:Item {
  id:          "uuid",           // matches items.id in PostgreSQL
  userId:      "uuid",           // for user-scoping all queries
  label:       "React Hooks Deep Dive",
  contentType: "url",            // image | pdf | url | text | audio | doc | video
  folder:      "Programming",    // denormalised folder name for fast filtering
  folderId:    "uuid",
  tags:        ["react", "hooks"],
  viewCount:   12,
  isStarred:   false,
  createdAt:   datetime("2026-04-12T10:23:00Z")
})
```

> **What is NOT stored on the node:** `raw_text`, `summary`, `embedding`, `storage_key`, `file_size`. These live in PostgreSQL only. Neo4j nodes are intentionally lightweight.

## 4. Relationship Types

### `SEMANTIC`

Generated by pgvector cosine similarity. Weight = cosine similarity score.

```cypher
(a:Item)-[:SEMANTIC {weight: 0.87, createdAt: datetime()}]->(b:Item)
```

- Weight range: 0.75 – 1.0 (threshold enforced at generation time)
- Max 5 per item (top-5 nearest neighbours)
- Bidirectional: always create both directions

### `SHARED_TAG`

Generated when two items share a tag that appears on fewer than 15% of the user's items.

```cypher
(a:Item)-[:SHARED_TAG {tag: "machine-learning", weight: 0.6}]->(b:Item)
```

- Fixed weight: 0.6
- One relationship per shared tag (not one per item pair)
- Bidirectional

### `TEMPORAL`

Generated when both items are part of a dense burst (≥3 items within 30 minutes).

```cypher
(a:Item)-[:TEMPORAL {weight: 0.35, deltaSeconds: 480}]->(b:Item)
```

- Weight range: 0.15 – 0.45 (decays with time delta)
- Max 3 per item (link to 3 temporally nearest burst neighbours)
- Directed: earlier item → later item

### `ENTITY_MATCH`

Generated when two items share a named entity (person, org, concept) extracted by Claude.

```cypher
(a:Item)-[:ENTITY_MATCH {entity: "OpenAI", entityType: "organisation", weight: 0.7}]->(b:Item)
```

- Fixed weight: 0.7
- Bidirectional

### `USER_LINK`

Manually created by the user via `POST /items/:id/link`.

```cypher
(a:Item)-[:USER_LINK {weight: 1.0, createdAt: datetime(), note: "optional user note"}]->(b:Item)
```

- Weight: always 1.0
- Directed (user decides source → target)
- Only edge type that can carry a user-written note

## 5. Indexes and Constraints

Run once on database initialisation (add to a migration script or startup check):

```cypher
-- Uniqueness constraint (also creates an index)
CREATE CONSTRAINT item_unique IF NOT EXISTS
  FOR (n:Item) REQUIRE n.id IS UNIQUE;

-- Lookup indexes
CREATE INDEX item_user IF NOT EXISTS
  FOR (n:Item) ON (n.userId);

CREATE INDEX item_folder IF NOT EXISTS
  FOR (n:Item) ON (n.userId, n.folder);

CREATE INDEX item_type IF NOT EXISTS
  FOR (n:Item) ON (n.userId, n.contentType);

-- Relationship index for weight filtering
CREATE INDEX semantic_weight IF NOT EXISTS
  FOR ()-[r:SEMANTIC]-() ON (r.weight);
```

## 6. Key Cypher Queries

### Full graph for a user (top-500 by degree)

```cypher
MATCH (n:Item {userId: $userId})-[r]-(m:Item {userId: $userId})
WITH n, count(r) AS degree
ORDER BY degree DESC
LIMIT 500
MATCH (n)-[r {weight: $minWeight}]-(m:Item {userId: $userId})
  WHERE r.weight >= $minWeight
RETURN n, r, m
```

### Ego graph — 2-hop neighbourhood

```cypher
MATCH (start:Item {id: $itemId, userId: $userId})
MATCH path = (start)-[r*1..2]-(neighbour:Item {userId: $userId})
  WHERE ALL(rel IN relationships(path) WHERE rel.weight >= 0.6)
RETURN start, relationships(path), nodes(path)
```

### Shortest path between two items

```cypher
MATCH (a:Item {id: $idA, userId: $userId}),
      (b:Item {id: $idB, userId: $userId})
MATCH path = shortestPath((a)-[*..6]-(b))
RETURN path
```

### Find bridge nodes (items connecting otherwise disconnected clusters)

```cypher
MATCH (n:Item {userId: $userId})
WITH n, apoc.node.degree(n) AS deg
WHERE deg >= 3
MATCH (a)-[]-(n)-[]-(b)
  WHERE NOT (a)-[]-(b) AND a.userId = $userId AND b.userId = $userId
RETURN n, count(*) AS bridgeScore
ORDER BY bridgeScore DESC
LIMIT 20
```

### Items connected to a tag cluster

```cypher
MATCH (n:Item {userId: $userId})-[:SHARED_TAG {tag: $tag}]-(m:Item)
RETURN n, m
```

### Delete all nodes and edges for a user (GDPR erasure)

```cypher
MATCH (n:Item {userId: $userId})
DETACH DELETE n
```

## 7. Python Driver Setup

```python
# packages/ai/graph/neo4j_client.py
from neo4j import AsyncGraphDatabase
from app.config import settings

class Neo4jClient:
    def __init__(self):
        self._driver = AsyncGraphDatabase.driver(
            settings.NEO4J_URI,
            auth=(settings.NEO4J_USER, settings.NEO4J_PASSWORD),
            max_connection_pool_size=50,
        )

    async def close(self):
        await self._driver.close()

    async def run(self, query: str, **params):
        async with self._driver.session() as session:
            result = await session.run(query, **params)
            return await result.data()

    async def merge_item(self, item: dict):
        """Upsert an Item node — safe to call multiple times."""
        await self.run("""
            MERGE (n:Item {id: $id})
            SET n.userId      = $userId,
                n.label       = $label,
                n.contentType = $contentType,
                n.folder      = $folder,
                n.folderId    = $folderId,
                n.tags        = $tags,
                n.viewCount   = $viewCount,
                n.isStarred   = $isStarred,
                n.createdAt   = datetime($createdAt)
        """, **item)

    async def create_semantic_edge(self, source_id: str, target_id: str, weight: float):
        await self.run("""
            MATCH (a:Item {id: $sourceId}), (b:Item {id: $targetId})
            MERGE (a)-[r:SEMANTIC]->(b)
            SET r.weight = $weight, r.createdAt = datetime()
            MERGE (b)-[r2:SEMANTIC]->(a)
            SET r2.weight = $weight, r2.createdAt = datetime()
        """, sourceId=source_id, targetId=target_id, weight=weight)

    async def get_ego_graph(self, item_id: str, user_id: str, depth: int = 2):
        return await self.run("""
            MATCH (start:Item {id: $itemId, userId: $userId})
            MATCH path = (start)-[r*1..$depth]-(neighbour:Item {userId: $userId})
            WHERE ALL(rel IN relationships(path) WHERE rel.weight >= 0.6)
            RETURN start, relationships(path) AS rels, nodes(path) AS nodes
        """, itemId=item_id, userId=user_id, depth=depth)

# Singleton — initialised at app startup
neo4j_client = Neo4jClient()
```

## 8. Performance Considerations

| Concern | Mitigation |
|---|---|
| Large user graphs (10k+ nodes) | Serve top-500 by degree centrality; lazy-load rest on demand |
| Cold query on first graph load | Redis cache, 1-hr TTL, warm on `item.ready` |
| Neo4j memory for concurrent users | Allocate 2G heap, 1G page cache; scale horizontally with AuraDB |
| APOC bridge query is expensive | Run as background job, cache result; don't call on every request |
| Relationship explosion on popular tags | Tag frequency threshold (≤15% of user items) prevents hairball graphs |
